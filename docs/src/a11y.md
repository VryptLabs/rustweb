# Accessibility (a11y)

- `aria-*` and `role` are first-class in `html!` and forwarded to the DOM/SSR output unchanged.
- ARIA typos are rejected at compile time with a suggestion.
- Recommended pattern: every interactive control has an accessible name
  (`aria-label`/`aria-labelledby` or content text); state uses
  `aria-pressed`/`aria-selected`/`aria-expanded`, never color alone.

## Built-in static audit

`rustweb_testing::a11y::check` walks a `VNode` tree and returns an
`A11yReport` of violations with severity (`Serious`, `Moderate`, `Minor`), a
human-readable `path`, a `rule` id, and a `fix_hint`. It runs on the host with
no browser, so it is enforced on every commit through `cargo test`.

Rules currently enforced:

- `interactive-name` (Serious): `button`, linked `a[href]`, `summary`, and
  interactive ARIA roles must expose an accessible name.
- `form-label` (Serious): text `input`, `textarea`, `select` must have a label.
- `image-alt` (Serious): `img` / `role=img` must carry `alt` (empty `alt=""` is
  valid for decorative images) or an ARIA label.
- `heading-order` (Moderate): heading levels must not increase by more than one.
- `list-structure` (Moderate): direct children of `ul`/`ol` must be `li`.
- `landmark-main` (Minor): the document should contain a `main` landmark.

## Usage

```rust,ignore
use rustweb_testing::a11y::check;

let report = check(&app_view());
assert!(!report.has_blocking(), "{}", report.to_text());
```

`example_is_a11y_clean` in `examples/todo-app` gates the shipped example so it
must audit with zero blocking violations. Because the linter is plain Rust it
runs inside the standard `cargo test` matrix job (all OSes/toolchains), so every
PR is checked. `axe-core` remains the complementary *runtime* audit to run
against a served app once trunk-parity dev-server output exists; the static
linter covers markup-level rules ahead of that.
